[![Live Demo](https://img.shields.io/badge/Demo-Live%20Website-emerald?style=for-the-badge&logo=googlechrome&logoColor=white)](https://project-sy789.github.io/School-Club-Registration-System/)

ระบบลงทะเบียนเลือกชุมนุมสำหรับนักเรียนระดับมัธยมศึกษาตอนต้นและตอนปลาย พัฒนาด้วย **Single Page Application (SPA)** และ Supabase โดยการตัดสินใจเรื่องที่นั่งอยู่ใน PostgreSQL transaction เดียว การรองรับ 800-1,000 คนต้องทดสอบกับขนาดโปรเจกต์และ quota ของ Supabase ที่เลือกก่อนเปิดรับสมัครจริง

## 🎨 จุดเด่นของระบบ (Key Features)

* **ดีไซน์พรีเมียมสีเขียวเอมเมอรัลด์ (Premium Emerald Glassmorphism):** หน้าเว็บตอบสนองรวดเร็ว ลื่นไหล มีเอฟเฟกต์สะท้อนแสง ทรานซิชันสวยงาม และรองรับการแสดงผลแบบ Responsive ในมือถือ 100%
* **ระบบตัวจับเวลาเปิด-ปิดอัตโนมัติ (Dynamic Live Countdown):** แสดงผลเวลาเปิดรับสมัครนับถอยหลังระดับมิลลิวินาที และเปิด/ปิดระบบให้ลงทะเบียนได้โดยอัตโนมัติโดยที่นักเรียนไม่ต้องกดรีเฟรชหน้าเว็บ
* **ระบบตัดยอดที่นั่งปลอดภัยสูงสุด (Row Lock Atomic Seats):** ใช้ฟังก์ชัน Stored Procedure บน PostgreSQL (`FOR UPDATE`) ในการล็อกที่นั่งก่อนเขียนทับ ทำให้มั่นใจว่าไม่มีทางเกิดปัญหา "ที่นั่งเรียนเกินโควตา" แม้จะยิงจองเข้ามาพร้อมกันในเสี้ยววินาทีเดียวกัน
* **Flow นักเรียนใหม่แบบ Pending:** นักเรียนที่ไม่มีรหัสต้องใช้เบอร์โทรศัพท์ผู้ปกครอง 10 หลักหรือรหัสสมัครชั่วคราวจากโรงเรียนรูปแบบ `TMP-XXXXXX` (ระบบไม่รับเลขบัตรประชาชน) รายการจะกันที่นั่งแบบมาก่อนได้ก่อนและรอผู้ดูแลจับคู่กับรหัสนักเรียนจริง การใช้ชื่อเดิมร่วมกับรหัสอื่นจะถูกปฏิเสธเพื่อป้องกันการจองซ้ำ
* **การบูรณาการคำนำหน้าชื่อตามมาตรฐานไทย (Title Prefix Integration) 🆕:** รองรับข้อมูลคำนำหน้าชื่อ (เด็กชาย, เด็กหญิง, นาย, นางสาว) ในระดับตารางฐานข้อมูลและหน้ารายงานผลทั้งหมด แสดงผลการรวมชื่อตามหลักไวยากรณ์ไทยอย่างเป็นทางการ (เช่น `นายสมชาย ใจดี` เขียนติดกันโดยไม่มีช่องว่างระหว่างคำนำหน้าและชื่อจริง) พร้อมระบบอัพโหลดแบบตรวจจับหัวตารางอัจฉริยะ (Header Detection Mapper) รองรับการนำเข้าไฟล์รายชื่อผ่าน Excel/CSV ทั้งแบบ 4 คอลัมน์เดิม และ 5 คอลัมน์ใหม่ได้อย่างปลอดภัย 100%
* **ระบบผู้ดูแลระบบอัจฉริยะ (Admin Dashboard):**
  * **รายงานสรุปเรียลไทม์:** รายงานสัดส่วนการจอง สถิติจำนวนที่นั่งของแต่ละชุมนุม
  * **ระบบอนุมัติเด็กใหม่:** แสดงตารางจัดการเด็กสมัครใหม่พร้อมกรอกรหัสและยืนยันตัวตน หรือสลับยกเลิกสิทธิ์
  * **จัดการชุมนุม:** ฟอร์มเพิ่ม ลบ หรือแก้ไขรายละเอียดชุมนุม ครูผู้สอน สถานที่เรียน โควตา และช่วงชั้นที่รับสมัคร (ม.1 - ม.6)
  * **ระบบ Bulk Import รายชื่อชุมนุม:** นำเข้ารายชื่อชุมนุมและโควตาทั้งหมดของโรงเรียนได้ในคลิกเดียวผ่านไฟล์ `.csv` 🆕
  * **ระบบ Bulk Import รายชื่อเด็ก:** นำเข้ารายชื่อนักเรียนเก่าได้เพียงลากและวางไฟล์ `.csv` ประมวลผลรวดเร็วผ่านคำสั่ง Upsert Batch
  * **ระบบ Bulk Import การลงทะเบียนชุมนุม (Admin Pre-Registration) 🆕:** ครูสามารถนำเข้ารายชื่อนักเรียนพร้อมชื่อชุมนุมในไฟล์ `.csv` เดียว เพื่อล็อกที่นั่งให้นักเรียนล่วงหน้าได้แบบ Bulk โดย**ไม่จำเป็นต้องนำเข้าฐานข้อมูลนักเรียนให้ครบก่อน** — แถวที่มีรหัสตรงกับฐานข้อมูลจะเป็น Verified ทันที, ที่เหลือจะเป็น Pending ให้ครูยืนยันสิทธิ์ทีหลัง พร้อมระบบเคารพโควตา (Capacity-Aware) Row Lock ป้องกัน Race Condition และรายงานสรุปผลรายแถว (สำเร็จ/ข้าม/ผิดพลาด) แบบสวยงาม
  * **ส่งออกเอกสาร Excel (Thai BOM CSV Export):** ส่งออกรายชื่อนักเรียนแยกตามชุมนุมหรือรวมทั้งโรงเรียนเป็นไฟล์ CSV ที่รองรับอักษรไทยสมบูรณ์แบบ เปิดใน Excel ภาษาไม่เพี้ยน ไม่เป็นตัวต่างดาว มีคอลัมน์คำนำหน้าชื่อแยกเรียบร้อย
  * **ระบบตรวจสอบประวัติย้อนหลังและความปลอดภัย (Audit Logs):** บันทึกการกระทำความปลอดภัยทั้งหมด (สมัครเรียนสำเร็จ, ลงสำรอง, ครูยืนยันสิทธิ์, ครูปฏิเสธ/ยกเลิกสิทธิ์, ครูตั้งค่าระบบ) พร้อมเก็บ **User Agent** และ IP ที่ระบบได้รับโดยตรงจากผู้ดูแล เพื่อไม่เพิ่ม network hop ให้ผู้สมัครจำนวนมากในช่วงเปิดรับสมัคร 🆕
  * **ระบบเลื่อนชั้น/เปิดเทอมใหม่ + ย้อนกลับเทอม (Promote & Rollback Term) 🆕:** ปิดเทอมและเลื่อนชั้นนักเรียนทุกคนได้ในคลิกเดียว (ม.3→ม.4, ม.6→จบการศึกษา) พร้อมเก็บประวัติการลงทะเบียนของทุกเทอมไว้ในตาราง `registrations` ตามคู่ `(academic_year, semester)` — และหากเปิดเทอมพลาด สามารถกดปุ่ม **"ย้อนกลับเทอม"** เพื่อย้อนกลับไปยังเทอมเก่าได้หลายปีหลายภาคเรียน ระบบจะคำนวณ `enrolled_count` ของชุมนุมใหม่อัตโนมัติจากข้อมูลในเทอมที่เลือก พร้อมบันทึก Audit Log ครบถ้วน
  * **กำหนดรูปแบบการสมัครได้ต่อโรงเรียน 🆕:** ในหน้าตั้งค่าหลังบ้านเลือกได้ทั้ง **แยกลงทะเบียนทุกภาคเรียน** หรือ **สมัครครั้งเดียวใช้ชุมนุมเดิมตลอดปีการศึกษา** โดยโหมดรายปีจะกันการสมัครซ้ำข้ามภาคเรียน รักษายอดที่นั่งเมื่อเปิดภาคเรียนที่ 2 และคำนวณยอดใหม่เมื่อเริ่มปีการศึกษาใหม่
  * **ระบบจัดการข้อมูลศิษย์เก่าตาม PDPA (Graduated Student Privacy) 🆕:** รองรับ พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล โดยครูสามารถ **ปกปิดชื่อ-นามสกุล** ของนักเรียนที่จบการศึกษาเกิน N ปี (แทนด้วยรหัสรูปแบบ `ศิษย์เก่า #YEAR-NNN`) หรือ **ลบถาวร** ข้อมูลศิษย์เก่ารายบุคคลได้ พร้อม Audit Log ทุกครั้ง

> 1. **กดปุ่ม `Fork`** ที่มุมขวาบนของหน้านี้บน GitHub → ตั้งค่าเป็น **Private** (ดู [ทางเลือกที่ 2](#-ทางเลือกที่-2-เปลี่ยนเป็นคลังเก็บโค้ดส่วนตัว-private-repository--deploy-ผ่านผู้ให้บริการฟรี) เพื่อกัน API key หลุด)
> 2. **สมัคร Supabase** (ฟรี) → รัน [`supabase/setup_database.sql`](supabase/setup_database.sql) แล้วรัน [`supabase/migrate_backend_hardening.sql`](supabase/migrate_backend_hardening.sql) ใน SQL Editor → คัดลอก **Project URL + anon Key** เก็บไว้
> 3. ที่ Fork ของคุณบน GitHub → เปิดไฟล์ **`config.js`** → กดรูป **ดินสอ ✏️** มุมขวาบน → นำ URL และ Key มาวางในเครื่องหมาย `""` ของตัวแปร `SUPABASE_CONFIG` → กด **Commit changes** ✅
> 4. ไปแท็บ **Settings → Pages → Source: Deploy from a branch → เลือก `main` → Save** ✅
> 5. สร้างผู้ใช้ผู้ดูแลใน Supabase Auth และเพิ่ม `user_id` ลงตาราง `admin_users` ตามคู่มือด้านล่าง → เปิดลิงก์ GitHub Pages และเข้าสู่หลังบ้านด้วยอีเมล/รหัสผ่านของผู้ดูแล
>
> *ทำเสร็จภายใน 5 นาทีโดยไม่ต้องติดตั้งโปรแกรมหรือเขียนโค้ดเอง!* 💚

> [!NOTE]
> หากต้องการความปลอดภัยสูงสุด (ไม่อยากให้ API key อยู่ในไฟล์โค้ดเลย) กรุณาทำตาม **3 ขั้นตอนหลัก** ด้านล่างนี้ตามลำดับ:

### 1️⃣ ขั้นตอนที่ 1: ตั้งค่าฐานข้อมูลหลังบ้าน (Supabase Setup)
1. สมัครสมาชิกหรือลงชื่อเข้าใช้งานที่ [Supabase](https://supabase.com) (ฟรี 100%)
2. กดปุ่ม **Create a new project** ตั้งชื่อโครงการและรหัสผ่านฐานข้อมูลให้เรียบร้อย (แนะนำให้เลือก Region เป็น **Singapore** เพื่อความรวดเร็วในการโหลดข้อมูลในประเทศไทย)
3. เมื่อสร้างโครงการเสร็จสมบูรณ์แล้ว ให้คลิกเมนู **SQL Editor** ที่แถบเครื่องมือซ้ายมือ (สัญลักษณ์รูป `SQL`)
4. คลิกปุ่ม **New Query**
5. คัดลอกเนื้อหาจากไฟล์ [supabase/setup_database.sql](supabase/setup_database.sql) มาวางและกด **Run** จากนั้นทำซ้ำกับไฟล์ [supabase/migrate_backend_hardening.sql](supabase/migrate_backend_hardening.sql)
6. **คัดลอกรหัสเชื่อมต่อ:** ไปที่เมนู **Settings** (รูปฟันเฟืองซ้ายล่าง) > **API** แล้วทำการคัดลอกค่า 2 ค่าต่อไปนี้เก็บไว้:
   * **Project URL** (เช่น `https://xxxxxx.supabase.co`)
   * **anon (public) Key** (รหัสคีย์สาธารณะขนาดยาว)

### 2️⃣ ขั้นตอนที่ 2: ตั้งค่าเชื่อมโยง API และเปิดใช้งานระบบ (มี 3 ทางเลือก - แนะนำวิธีที่ 1 เพื่อความปลอดภัยสูงสุด 🛡️)

> [!WARNING]
> **เรื่องสำคัญมากด้านความปลอดภัย:** การนำ **Project URL** และ **anon Key** ไปเขียนลงในไฟล์ `config.js` ตรง ๆ แล้วอัปโหลดขึ้น GitHub สาธารณะ (Public) จะทำให้รหัส API หลุดสู่สาธารณะและถูกสแกนเจาะข้อมูลได้!

> ดังนั้น เพื่อป้องกันรหัสผ่านหลุดและทำให้ระบบปลอดภัย 100% ขอแนะนำให้ใช้ **วิธีที่ 1** หรือ **วิธีที่ 2** ด้านล่างนี้ครับ:

#### 🔒 ทางเลือกที่ 1: ใช้ GitHub Secrets + GitHub Actions (แนะนำที่สุดสำหรับคลังเก็บโค้ดสาธารณะ 🌟)
ระบบของเราได้เตรียมไฟล์สั่งการอัตโนมัติ (Workflow) ไว้ให้แล้ว คุณสามารถฝากค่ากุญแจเชื่อมต่อไว้ในระบบความปลอดภัยของ GitHub (Secrets) โดย**ไม่ต้องแก้ไขไฟล์โค้ดใด ๆ ในโปรเจกต์เลย** ซึ่งมีขั้นตอนง่าย ๆ ดังนี้:

1. **ตั้งค่ารหัสลับใน GitHub (Secrets):**
   * ไปที่หน้าโปรเจกต์ของคุณบน GitHub -> คลิกแท็บ **Settings** (รูปฟันเฟืองด้านบนสุด)
   * ที่เมนูด้านซ้ายมือ เลื่อนลงมาที่หัวข้อ **Security** -> คลิกเลือก **Secrets and variables** -> เลือก **Actions**
   * คลิกปุ่มสีเขียว **New repository secret** (มุมขวาบน)
   * **สร้างคีย์ที่ 1:** ในช่อง Name ใส่ว่า `SUPABASE_URL` และในช่อง Value นำ **Project URL** ที่ได้จาก Supabase มาวาง แล้วกด **Add secret**
   * **สร้างคีย์ที่ 2:** คลิก **New repository secret** อีกครั้ง ในช่อง Name ใส่ว่า `SUPABASE_ANON_KEY` และในช่อง Value นำ **anon Key** จาก Supabase มาวาง แล้วกด **Add secret**

2. **เปิดสิทธิ์การใช้งาน GitHub Actions Deploy:**
   * ที่เมนูตั้งค่าซ้ายมือ คลิกหัวข้อ **Pages**
   * ในหัวข้อ **Build and deployment** -> ตรงช่อง **Source** ให้คลิกเลือกเปลี่ยนจาก `Deploy from a branch` เป็น **`GitHub Actions`** ⚙️

3. **เริ่มต้นใช้งานจริง:**
   * ไปที่แท็บเมนู **Actions** (แถบเมนูด้านบนของหน้าเว็บ)
   * คลิกเลือก Workflow ชื่อ **"Deploy to GitHub Pages"** ที่แถบเมนูด้านซ้าย
   * คลิกปุ่ม **Run workflow** -> เลือก Branch เป็น `main` แล้วกดปุ่มสีเขียว **Run workflow**
   * ระบบจะทำการสร้างหน้าเว็บความปลอดภัยสูงและอัปเดตลงลิงก์ GitHub Pages ให้คุณทันทีใน 1 นาที! ลิงก์เข้าใช้งานจะปรากฏอยู่บนหน้าจอครับ

#### 🔒 ทางเลือกที่ 2: เปลี่ยนเป็นคลังเก็บโค้ดส่วนตัว (Private Repository) + Deploy ผ่านผู้ให้บริการฟรี
หากต้องการความเป็นส่วนตัวสูงสุด ไม่อยากเปิดเผยหน้าซอร์สโค้ด และไม่มีทักษะด้านเทคนิคสูง:
1. ไปที่แท็บ **Settings** ของโปรเจกต์บน GitHub -> เลื่อนลงไปล่างสุดที่หัวข้อ **Danger Zone**
2. คลิกปุ่ม **Change visibility** แล้วเปลี่ยนเป็น **Private** (คลังเก็บโค้ดส่วนตัว - ฟรี 100%)
3. จากนั้นคุณสามารถเข้าไปแก้ไขไฟล์ **`config.js`** บนหน้าเว็บ GitHub เพื่อใส่รหัสเชื่อมต่อตามปกติได้ทันที โดยไม่มีบุคคลภายนอกมองเห็นไฟล์ของคุณได้เลย
4. **การ Deploy:** แนะนำให้ใช้ [Netlify](https://netlify.com) หรือ [Vercel](https://vercel.com) (สมัครฟรี 100%) เชื่อมต่อเข้ากับ GitHub Account ของคุณ แล้วเลือกดึงโปรเจกต์ส่วนตัวนี้ไปเปิดใช้งานแบบคลิกเดียวจบ!

#### ⚠️ ทางเลือกที่ 3: แก้ไขไฟล์ `config.js` ตรง ๆ บน GitHub (ง่ายที่สุด สำหรับทดสอบระบบ/ไม่ซีเรียสเรื่องกุญแจหลุด)
*ใช้ในกรณีที่คุณนำระบบไปรันเล่น ๆ หรือไม่มีข้อมูลสำคัญใด ๆ เท่านั้น:*
1. ไปที่หน้าแรกของคลังเก็บโค้ดบน GitHub คลิกเลือกเปิดไฟล์ชื่อ **`config.js`**
2. คลิกปุ่ม **รูปดินสอ ✏️ (Edit this file)** บริเวณมุมขวาบนของโค้ด เพื่อแก้ไขไฟล์ในบราวเซอร์ทันที
3. นำค่า **Project URL** และ **anon Key** มาวางแทนที่ในเครื่องหมายคำพูดคู่ `""` ของตัวแปร `SUPABASE_CONFIG` จากนั้นกดปุ่ม **Commit changes...** ด้านบนขวาเพื่อบันทึก
4. ไปที่ **Settings** > **Pages** -> เลือก Build from branch เป็น **`main`** แล้วกด **Save** เป็นอันเสร็จสิ้นครับ!

## 🔒 ตั้งค่าผู้ดูแลระบบ (Supabase Auth)

1. ไปที่ Supabase **Authentication → Users → Add user** และสร้างบัญชีอีเมล/รหัสผ่านของครูผู้ดูแล
2. คัดลอก UUID ของผู้ใช้ แล้วรัน SQL นี้ใน SQL Editor:

```sql
insert into public.admin_users (user_id)
values ('ใส่-UUID-ของผู้ดูแลที่นี่');
```

3. ปิดการสมัครสมาชิกสาธารณะใน **Authentication → Providers → Email** เพื่อไม่ให้บุคคลทั่วไปสร้างบัญชีเอง
4. หลัง migration แล้ว ผู้ใช้ anonymous จะอ่านตารางนักเรียน/ผู้สมัครไม่ได้ หน้าแอดมินจะใช้ Supabase Auth และตรวจสิทธิ์จาก `admin_users`

รหัสบัตรประชาชนไม่ควรถูกใช้เป็นตัวระบุสำรอง ระบบรับเฉพาะเบอร์โทรศัพท์ผู้ปกครอง 10 หลักที่ขึ้นต้นด้วย 0 หรือรหัสสมัครชั่วคราวรูปแบบ `TMP-XXXXXX` สำหรับรายการ Pending และเก็บค่าดังกล่าวในรูป hash กับเลขท้าย 4 หลักเท่านั้น

## 🧭 Flow การจองและการรองรับโหลด

นักเรียนที่มีรหัสต้องส่งรหัส ชื่อ และห้องให้ตรงกับตาราง `students` จึงจะได้สถานะ `verified` นักเรียนใหม่ใช้รหัสสมัครชั่วคราวหรือเบอร์โทรศัพท์ผู้ปกครอง จะได้สถานะ `pending` แต่ยังกันที่นั่งไว้ตามลำดับเวลาที่ฐานข้อมูลรับคำขอ ผู้ดูแลจะผูก Pending เข้ากับรหัสนักเรียนจริงหรือยกเลิกเพื่อคืนที่นั่งได้ใน RPC เดียว

การล็อกแถว `clubs ... FOR UPDATE`, unique index ต่อ `(student_id, academic_year, semester)`, advisory lock ของตัวตน และ registration token ทำให้คำขอซ้ำและการแย่งที่นั่งถูกตัดสินในฐานข้อมูลเดียว โหมด `semester` อนุญาตให้นักเรียนสมัครใหม่ในภาคเรียนถัดไป ส่วนโหมด `academic_year` จำกัดหนึ่งชุมนุมต่อปีการศึกษาและนับที่นั่งรวมทั้งปี การทดสอบ 800-1,000 คนควรยิงไปยัง RPC เดียวจากเครื่องทดสอบแยก และตรวจยอด `enrolled_count` กับจำนวนแถวจริงหลังจบการทดสอบ

## ♻️ Supabase Free และการพักโปรเจกต์

Supabase Free สามารถพัก (pause) โปรเจกต์เมื่อไม่มีการใช้งานตามนโยบายของ Supabase และไม่มีปุ่มหรือ SQL ที่รับประกันให้ฐานข้อมูลทำงานถาวรบนแผนฟรีได้ โปรเจกต์ที่ถูกพักแล้วต้องกด Restore/Resume ใน Supabase Dashboard ก่อนจึงจะกลับมาให้บริการได้

โปรเจกต์นี้เตรียม workflow [`supabase-keepalive.yml`](.github/workflows/supabase-keepalive.yml) ไว้เรียก RPC `healthcheck` สัปดาห์ละ 2 ครั้ง เพื่อลดโอกาสถูกมองว่าไม่มีการใช้งาน:

1. ใส่ `SUPABASE_URL` และ `SUPABASE_ANON_KEY` ใน GitHub **Settings → Secrets and variables → Actions** ของ repository เดียวกับ workflow deploy
2. ตรวจว่า GitHub Actions เปิดใช้งาน และกด **Actions → Keep Supabase project active → Run workflow** เพื่อทดสอบครั้งแรก
3. ตรวจผลในแท็บ **Actions** ว่างานสำเร็จและได้ response จาก RPC

วิธีนี้ช่วยลดความเสี่ยงแต่ไม่ใช่ SLA: GitHub อาจหน่วงหรือหยุด scheduled workflow โดยเฉพาะ repository ที่ไม่มี activity นานกว่า 60 วัน และ Supabase อาจเปลี่ยนนโยบายการพักโปรเจกต์ หากระบบต้องออนไลน์ตลอดจริงควรใช้ Supabase Pro หรือผู้ให้บริการฐานข้อมูลที่มี uptime guarantee

python3 -m http.server 8080

จากนั้นเปิดบราวเซอร์แล้วไปที่ `http://localhost:8080` เพื่อทดลองใช้งานครับ!
